## 阅读路径

总看板 -> 周 / 月看板及独立筛选 -> 周期概况 -> 发布节奏、事件构成、产品技术主题 -> 事件时间轴 -> 产品技术 / 合作动态 -> 分角色公司动态 -> 公司本期记录 / 已保留历史 -> 事件与原文证据。

最新新闻只显示 3 条，按发布日期降序，不按筛选分或优先指数排序。发布日期仅精确到日，同日按稳定 ID 排列，不宣称日内先后。

## 当前口径

- 周看板默认本周，周一至周日；月看板默认自然月。按日本时间计算当前日期和周期。
- 地区多选、商业事件、产品技术主题、公司、角色和检索词相互独立。地区内部为 OR，各维度之间为 AND。
- 总看板及周期页基础集合不按日报分层或优先分截取；仅总看板的重大信号指标保留既有入选且高相关子集。基础采集、原始情报的准入分层和后台频率没有修改。
- 事件记录：当前筛选中按相同链接 / 同日同标题保守合并的记录。不是已完成语义聚类的现实事件数。
- 公司数：事件命中的监测公司 ID 去重，不能与配置公司数或 232 个账户目录数混用。
- 产品技术：主商业事件为 product_platform 或 target_therapy；合作交易：partnership_deal。继续使用原有规则分类，标题与证据优先呈现，类别并不证明存在真实新品或交易。
- 每日柱形合计 = 事件记录数；商业事件构成合计 = 事件记录数。地区、主题和公司允许一条事件多命中，不应相加作为总数。
- 公司列表分竞品、账户、本公司，只显示本期有记录的公司；按本期数量降序，同量沿用竞争相关序号，再按 ID 排列。既有公司池与分组不变。
- 一律不把监测账户当成已确认客户；新总览不生成负责人或销售任务。

## 日期与事实边界

总览使用原始新闻发布日期。无效日期、未知日期、未来发布日期不计入当前周期。旧数据将活动来源日期直接复制为 event_start_at，不能当作已确认活动发生日；Sitemap 发现日期与 ClinicalTrials 登记更新日期也不能当新闻发布时间。这些记录从“日期待核对”独立入口查询，不在周期统计中冒充发生事件。

事件发生时间仅在 date_provenance.event_verified 有明确标记时展示为已确认时间；当前资料不足的保持“未确认”。没有使用甘特图，也没有根据发布日期编造起止日或项目周期。

产品 / 技术主题来自标题、原始摘录中的字面词，以及原有靶点 / 疗法字段在原文中实际出现的词。不把推断出的 product_needs 当成已发布产品。地区仅取标题 / 原始摘录，不以总部或来源名称推定。

原文标题保留；没有可信中文标题时不换成“某公司某类信号”的假翻译。摘要使用已有精读内容或原始摘录，没有独立正文信息时明确提示。英文精读不存在时显示原始摘录，不使用旧模板派责摘要充当翻译。

合作详情保留涉及公司与原始标题 / 摘录，但不会仅凭两家公司都被命中就新增合作关系。未核实的合作方、条款、产品名称和阶段不补猜。

## 事件保留

- data/latest_run.json：仍是本轮采集快照，不改采集逻辑。
- data/history/*.json：既有每日统计快照，原样保留，不能还原当日完整事件。
- data/event_archive.json：构建分享页时，以允许公开的事件字段逐轮增量保留。记录移出最新快照后仍可查询；不导入内部客户标记。
- 首轮只是当前快照的保留。上线前的历史日期仅代表各来源返回的回溯样本，不宣称完整覆盖。模拟两轮保留通过测试，不等于已经执行了未来的定时运行。
- 在线读取最新快照与归档；离线文件嵌入当前快照和已移出快照的保留记录，避免重复嵌入。同步失败明确标注旧快照或历史缺失。
- 沿用现有工作日 GitHub Actions；构建命令和 data/*.json 提交范围已覆盖新增归档。没有改 cron，没有新后端、数据库迁移或模型 API。
